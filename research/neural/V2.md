# Current-action learning: staged implementation

Historical milestone. Current GPU residency, captured updates, free placement and
confirmation defaults are documented in [GPU_REFACTOR.md](GPU_REFACTOR.md).


Approved objective: improve audited triangle reduction using standalone neural
proposals. Classical methods are offline teachers and separately reported
controls. Source and previous **emitted LOD** visual gates, protocol v3 SCORE,
source-stream ownership and reuse IDs remain unchanged. Overdraw breaks only
equal-triangle/equal-byte ties. Texture images/normal maps remain unsupported.

## Evidence and budget

The v1 run decreased loss from 0.538 to 0.222 and saturated its GPU, but both
25k/50k eight-asset pilots had eight fallbacks and SCORE 0. It stopped at step
52,224 on export disagreement. The failed state was not saved; replaying 51,200
cannot establish the exact cause of that failure. Collected archive SHA-256:
`907b4dc8ce1d1f9da4a50287c904d8e9505146e0255c23e1d34b7fb02c5fe933`.

User cap: **$10 total**, approximately **$2.75 already spent**. Reconcile live
billing/resources before provisioning. Reserve at least $1 for storage/setup
uncertainty; never launch an unbounded job. At the previously observed $2.09/h,
2.5 additional hours cost $5.225 before storage/tax. No local training.

## Implementation sequence

1. Preserve failed weights, optimizer, exact input and expected outputs before
   verification. Add no-training layer replay against an independent FP64
   oracle; explicitly reject NaN/Inf. Keep the original 2e-4 export gate.
2. Execute directed current-state endpoint collapses with reversible edits,
   topology/UV/material checks and dynamic re-ranking. Keep seam wedges distinct;
   ambiguous seam topology remains locked. Audit fixed source/previous-LOD
   references, including area, before accepting proposals.
3. Version action labels/models separately from v1. Begin with a two-hidden-layer
   width-64 edge MLP: rank plus source/adjacent pass predictions. Label only
   queried legal actions, preserve multiple safe preferred choices and unknowns.
   Query 8 teacher, 4 random, 4 policy candidates (random until a policy exists).
   Use margin 1, two auxiliary BCE terms weighted .25, logit penalty 1e-4;
   sample category, asset, progress state, then action. Keep these tunable.
4. One-mesh gate: >=95% preferred-set membership and >=90% of the offline
   teacher's audited reduction. Stop on failure; runtime never invokes a teacher.
5. Matched pilot: three random seeds, constant/shuffled/shortest-edge/QEM controls
   using identical executor, inputs, views and work budgets. Require reductions
   in two categories and >=1 SCORE point over strongest constant/shuffled
   control, persisting at the next checkpoint. Never score incomplete batches.
6. Optimize measured bottlenecks only after correctness: resident tensors and
   weights, reused buffers, batched actions, async metrics. FP32 first; BF16
   hidden layers only after parity evidence. Capture forward/backward if useful;
   keep C++ AdamW outside CUDA graphs because its step counter lives on the host.
7. Segment placement alpha in [0,1] follows endpoint proof; arbitrary XYZ and
   a more expensive GNN require additional evidence. Preserve chart attributes.

Every stage receives focused CTest/sanitizer checks and a pushed commit before
paid execution. New training gets short five-minute evidence gates and stops
after two flat audits; one extra five-minute window is allowed only if an
intermediate action metric improves. A healthy process alone is not completion.

## Current action implementation

`ActionState` owns current indices and CSR topology and borrows immutable vertex
streams. A directed endpoint edit has a revision, rejects stale IDs, checks the
geometric link, duplicate faces, orientation, UV foldovers and material junctions.
Unambiguous seam pairs collapse together while keeping separate endpoint wedge
attributes. Disconnected coincident fans, nonmanifold edges and ambiguous wedge
destinations remain locked. Trials preserve the incumbent until committed.
Every accepted edit rebuilds current features and re-ranks legal actions.

The executor now batches up to 32 actions by default (`--action-batch 1..64`).
Their closed endpoint one-rings must be disjoint on the geometric CSR, including
all coupled seam wedges. Each combined candidate receives the same full audits;
rejection halves the batch down to a singleton. Accepted batches rebuild and
re-rank once. `action_trials` counts joint candidate audits; accepted/rejected
action counters count contractions. Batch size enters the benchmark resume hash.

Repeated source-rejected endpoint candidates are memoized by exact indices and
material IDs, under an exact audit-settings key. The bounded cache retains at
most 4 MiB of payload and 64 entries; it never accepts a candidate, skips the
preceding-LOD gate for a source-passing candidate, or weakens final confirmation.
Cache hits still consume the deterministic candidate trial budget.

Portable architecture 2 contains **9,539 FP32 parameters**: 80 input features,
two 64-wide hidden layers, rank/source/adjacent heads. The v1 reader remains
supported. Native CUDA keeps weights and bounded scratch across calls, uses
pedantic FP32 GEMM and chunks large row counts. Topology and feature preparation
are currently CPU operations; this phase does not claim full GPU execution or
production throughput. `action_trials` defaults to 64 per proposal, is independent
of chain proposal counts, and is reported with the number of actions ranked.

Guarded proposals receive the fixed source, preceding emitted LOD and both full
audit settings from the chain search. CPU confirmation still checks the selected
chain. The render-cost tiebreak and protocol v3 SCORE are unchanged.

### Training and bounded proof commands

```sh
build/neural/blitz-neural-action-prepare ph_sweet_potato RUN/data --states 64 --pixels 32 --minutes 4
build/neural/blitz-neural-action-train RUN/data RUN/train --steps 4096 --minutes 4 --seed 101
build/neural/blitz-neural-action-proof RUN/train/step-4096.blzn RUN/data RUN/proof.json --minutes 2
```

The preparer accepts only the frozen training selection, verifies source hashes,
and stores versioned queried-action labels. Candidate pools contain up to 8
plane-error teacher choices, 4 random choices and 4 policy choices (random before
a model exists). Safe teacher costs within 25% plus 1e-10 of the best queried
cost form the preferred set; these are heuristic teachers, not optimal labels.
Optional `--model` collects policy-visited states. This first proof is one
scheduled transition, so the preceding emitted LOD is the original source.
It is not yet a diverse multi-level curriculum or a generalization experiment.

For a multi-level shard, `--previous-steps N` first performs N audited actions at
twice the requested pixel size (capped at 512), confirms and freezes that reduced
LOD, then collects `--states N` at the requested size. `--source-limit` and
`--adjacent-limit` independently condition the audit and network features. Failure
to emit a reduced preceding LOD leaves the shard incomplete. Each trajectory
records reference triangles and pixel size. The default single-transition proof
command and its fixed 3 px limits retain their original contract.
Multi-level shards also cycle requested target fractions 0.02/0.1/0.5/0.9, avoiding
the proof's constant 0.1 target conditioning during broader training.

A failed view is a valid negative label even when the evaluator skips later
views. Only an actual witnessed pixel/area failure is accepted as that verdict.
Cancellation before a verdict, resource failures and NaNs remain unknown and
stop the incomplete preparation. This distinction fixes the original preparer's
incorrect treatment of every early rejection as a data-generation failure.

Training keeps padded states resident on the GPU. Sampling chooses category,
asset, progress bin and state; multiple condition shards for one asset remain
one asset in that sampler. A dataset collection's `index.json` has a `datasets`
array of relative dataset-directory paths. Unqueried/padded choices own no loss.
Several preferred alternatives are supported. AdamW remains outside any CUDA
graph; BF16 and graph capture are gated on later measured benefit.

Checkpoint verification saves optimizer, model, input and expected/native outputs
before checking FP32/FP64 agreement and exact optimizer restoration. Failed
bundles can be replayed without training:

```sh
build/neural/blitz-neural-action-train --replay RUN/train/forensic/step-N replay.json
```

`--check [UNTRAINED_MODEL]` checks inference, FP64 agreement and loss gradients
without an optimizer update. The proof tool compares neural, constant, shortest
edge, plane-error QEM and three shuffled rankings using the same executor,
references and trial cap. Preferred membership is measured among the queried
training pools; this is deliberately an overfit proof. It requires >=95%
membership and >=90% teacher reduction, with CPU confirmation. Its single
transition measurements are **not a protocol SCORE**.

Local smoke: 64 queries across four states on the 2,042-triangle sweet potato
accepted four collapses, produced 2,034 triangles and passed CPU confirmation.
A random model achieved the same reduction as all controls but only 50%
preferred membership; the proof correctly failed. This is executor evidence,
not learning evidence. No local optimizer step was run.

### Cloud proof

`node research/neural/runpod.mjs prepare-actions RUN` bundles pushed source,
selected training meshes and the frozen development pilot. `launch RUN` then
reconciles live Pods, volumes and billing. It refuses existing resources and
caps the new rental at 60 minutes including setup/collection, with a 20-minute
remote experiment limit. The cumulative budget uses the greater of provider
billing and the conservative $2.75 prior estimate, the $2.50/hour maximum
compute rate plus storage allowance, and a $1 reserve under the $10 total cap.

The remote runner checks three seeds sequentially, with <=4-minute training
segments and <=2-minute proof audits. A passed endpoint gate must persist at the
next checkpoint. Two flat action audits stop a failing seed and the experiment.
Numerical, restore, memory or incomplete-audit failures stop immediately.
Automatic checksum collection and resource deletion use the existing independent
watchdog. Endpoint success hands off to matched development generalization;
it does not authorize a quality claim or automatically enable segment placement.

## Matched generalization comparison

After endpoint proof, `action-pilot.mjs OUTPUT MODEL1 MODEL2 MODEL3` runs three
independent models and constant, three shuffled, shortest-edge and current-plane
controls on the frozen eight-asset pilot. `--previous REPORT` requires the same
inputs/settings/binary and a new checkpoint for every seed before marking an
advantage as persistent. Incomplete batches have no accepted comparison. The
runner has a 45-minute total default, <=5-minute batches, and stops on the first
incomplete batch. It never rents a GPU itself.

CLI controls are `--action-trials N --neural-control learned|constant|shuffled|shortest|current-plane --ranking-seed N`.
Controls have distinct method names in reports; all settings and seeds enter the
resume hash. The normal model path uses only the learned ranking.

**Separate minimum-triangle scenario:** `action-pilot.json` explicitly sets
`triangle_overhead_bps: 0`, matching the approved triangle-first learning goal.
All source/adjacent pixel and area limits, views and SCORE formula are unchanged.
Run every control with that same file. The old v1 experiment's 5% storage-tradeoff
scores are not its baseline; the production default remains 5%.

Why this distinction matters: in the two-mesh, two-trial smoke, the untrained
policy made 24 audited collapses across 12 stool proposals. A valid candidate had
6,528 triangles versus 6,532 originally. The 5% storage selector intentionally
chose the original mesh (222,064 resident bytes) over that tiny reduction
(300,400 bytes including its additional index buffer). This was neither an audit
failure nor evidence of learned quality. Constant and learned smoke runs retain
their raw results under `runs/neural/v2-diagnostics/control-smoke-*`.

## Verified endpoint proof and bounded continuation

The RTX PRO 6000 run from source `ffbf34e` passed the endpoint gate for all three
seeds at both 4,096 and 8,192 updates. Final preferred membership: 100%, 98.4375%,
100%. All models and controls achieved 128 removed triangles; no superiority is
claimed from that quota. Native/FP64 maximum error was approximately 5.154e-5,
and exact optimizer restoration passed. The complete proof took approximately
195 seconds. Training utilization averaged 38.2%; auditing averaged 72.23%.
Artifacts and the subsequent batching smoke are in [evidence/action-v2](evidence/action-v2/README.md).

`prepare-action-pilot RUN` bundles the verified endpoint artifacts and the same
allowed training/pilot assets. This mode reserves at most 90 minutes of rental
and 50 minutes of experiment time, still enforcing the cumulative $10 cap with
a $1 reserve and charges from earlier failed/successful action rentals. It
collects policy-visited states on sweet potato and painted wooden bench at
16/64/256 px, including fixed preceding LODs at 32/128/512 px. These are early
trajectory states from two assets, not broad corpus training.
Cloud preparation and all matched methods use an explicit 16 GiB CUDA scratch
allowance on the 96 GB card. The local high-pixel probe ran out of available
device memory while Unity and the desktop were using most of the 8 GB card;
it remains incomplete. Detailed failure diagnostics are retained.
The larger cloud allowance changes capacity, not sampling or acceptance limits.

The first curriculum run produced all 164 states and healthy checkpoints for
three seeds (98.78–99.39% queried preferred membership), but its pilot stopped
because the benchmark CLI lacked the requested GPU-memory option. Results were
collected and all resources deleted. The option is now implemented and checked
by a CLI contract test before paid execution. [Saved curriculum evidence](evidence/action-curriculum-v2/README.md)
includes the immutable shards; subsequent runs verify and reuse them.

The runner trains three fresh seeds at 8,192 and 16,384 updates. Each checkpoint
must pass finite-output, unchanged export-tolerance and exact restoration gates;
numerical probes span the entire dataset collection. Each stage then runs all
nine matched pilot methods. A second comparison starts only if the remaining
time can accommodate the previous comparison's duration plus a minute. Incomplete
comparisons stay unscored. There is no automatic third stage, BF16, segment
placement or release promotion. All results are collected and the independent
watchdog enforces shutdown even if the experiment fails.

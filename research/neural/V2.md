# Current-action learning: staged implementation

Approved objective: improve audited triangle reduction using standalone neural
proposals. Classical methods are offline teachers and separately reported
controls. Source and previous **emitted LOD** visual gates, protocol v3 SCORE,
source-stream ownership and reuse IDs remain unchanged. Overdraw breaks only
equal-triangle/equal-byte ties. Texture images/normal maps remain unsupported.

## Implementation sequence

1. Preserve failed weights, optimizer, exact input and expected outputs before
   verification. Add no-training layer replay against an independent FP64
   oracle; explicitly reject NaN/Inf. Keep the original 2e-4 export gate.
2. Execute directed current-state endpoint collapses with reversible edits,
   topology/UV/material checks and dynamic re-ranking. Keep seam wedges distinct;
   ambiguous seam topology remains locked. Audit fixed source/previous-LOD
   references, including area, before accepting proposals.
3. Version action labels/models separately from v1. Begin with a two-hidden-layer
   width-64 edge MLP: rank plus source/adjacent pass predictions. Label only
   queried legal actions, preserve multiple safe preferred choices and unknowns.
   Query 8 teacher, 4 random, 4 policy candidates (random until a policy exists).
   Use margin 1, two auxiliary BCE terms weighted .25, logit penalty 1e-4;
   sample category, asset, progress state, then action. Keep these tunable.
4. One-mesh gate: >=95% preferred-set membership and >=90% of the offline
   teacher's audited reduction. Stop on failure; runtime never invokes a teacher.
5. Matched pilot: three random seeds, constant/shuffled/shortest-edge/QEM controls
   using identical executor, inputs, views and work budgets. Require reductions
   in two categories and >=1 SCORE point over strongest constant/shuffled
   control, persisting at the next checkpoint. Never score incomplete batches.
6. Optimize measured bottlenecks only after correctness: resident tensors and
   weights, reused buffers, batched actions, async metrics. FP32 first; BF16
   hidden layers only after parity evidence. Capture forward/backward if useful;
   keep C++ AdamW outside CUDA graphs because its step counter lives on the host.
7. Segment placement alpha in [0,1] follows endpoint proof; arbitrary XYZ and
   a more expensive GNN require additional evidence. Preserve chart attributes.

Every stage receives focused CTest/sanitizer checks and a pushed commit before
paid execution. New training gets short five-minute evidence gates and stops
after two flat audits; one extra five-minute window is allowed only if an
intermediate action metric improves. A healthy process alone is not completion.

How efficient pipelines handle this

Capabilities already in use and the next optimizations to measure.

Already implemented

Reuse labels and device storage

Earlier verified training shards are reused. Training tensors, source mesh streams and reusable audit scratch stay on the GPU. This avoids repeating preparation or downloading full raster images during normal audits.

Audit optimization to measure

Cache reference images; batch independent views

Unchanged references are still rendered for each comparison, and cameras run sequentially. A bounded cache and concurrent view work could avoid repeated computation and waits. Exact cache keys, memory limits and audit decisions must be preserved.

Scheduling and setup to improve

Reuse verified builds; choose evaluation checkpoints

Keep frequent numerical health checks. Use cheap progress diagnostics between selected full mesh comparisons, and reuse a compatible verified build. Final visual acceptance and the matched comparison protocol remain unchanged. The existing run already evaluates at two training endpoints.

Trainer optimization to profile

Reduce short launches and synchronization

Each step currently uploads sample IDs and reads scalar loss and gradient health. Profile batching, asynchronous reporting and CUDA graphs while retaining failure detection and optimizer correctness. The small model’s low GPU busy time is not a reason to enlarge it.
